# Telegram Sender / Parser

Проект для входа в Telegram-аккаунт, рассылки по списку, архивации диалогов и сбора участников из групп/каналов.

## Обычный запуск через батники (на Linux вместо двойного клика запускать через команду <code>bash <имя скрипта></code> на файлах с расширением <code>.sh</code>)

Используйте этот вариант, если не хотите запускать команды вручную. Просто открывайте нужные `.bat` файлы двойным кликом и следуйте подсказкам в окне.

### Первый запуск

1. Откройте `установка.bat`.
2. Откройте `войти acc1.bat`.
3. Отсканируйте QR-код через Telegram.

### Рассылка

Откройте:

```text
запуск acc1.bat
```

### Архивация диалогов

Откройте:

```text
архивация acc1.bat
```

### Сбор участников

Откройте:

```text
сбор участников acc1.bat
```

В окне выберите группу/канал и способ сбора. Готовый список сохранится в папку `lists`. При сборе комментаторов рядом появится Excel-файл `*_comments.xlsx`: ник, ссылка, комментарий и дата.

## Самостоятельный запуск через терминал

Этот вариант нужен, если вы хотите запускать проект командами, менять настройки руками или понимать, откуда берутся списки, сообщения и прогресс.

Все команды ниже выполняются из корня проекта в PowerShell.

### Установка

```powershell
npm install
```

### Файл настроек аккаунта

Для `acc1` используется файл `.env.acc1`. Если его ещё нет, создайте из примера:

```powershell
Copy-Item example.env.acc1 .env.acc1
notepad .env.acc1
```

Главное, что обычно меняется в `.env.acc1`:

- `SESSION_STRING` - строка сессии Telegram. Можно оставить пустой, после входа сохранится автоматически.
- `LIST_FILE` - имя списка из папки `lists`.
- `MESSAGE_FILES` - имя файла сообщения из папки `messages`. Несколько файлов можно указать через запятую.
- `PROFILE=acc1` - имя профиля.
- `STORAGE_MODE=shared` - общий прогресс, `per_profile` - отдельный прогресс в `storage/acc1`.
- `REPORT_FILE` - путь к отчёту, если нужен нестандартный.
- `SOCKS_PROXY` и `SOCKS_TYPE` - прокси, если используется.
- `STICKER_SET_INDEX` и `STICKER_DOC_INDEX` - какой стикер брать из наборов аккаунта.
- `SCHEDULE_HOUR` и `SCHEDULE_MINUTE` - время запуска для планировщика.

### Вход через QR без рассылки

```powershell
npm run login:acc1
```

После сканирования QR-кода `SESSION_STRING` будет записан в `.env.acc1`.

Для других аккаунтов:

```powershell
npm run login:acc2
npm run login:acc3
```

### Рассылка

```powershell
npm run start:acc1
```

Скрипт берёт получателей из `lists/<LIST_FILE>`, сообщения из `messages/<MESSAGE_FILES>` и продолжает с сохранённого места, если запуск уже был.

### Архивация

```powershell
npm run archive:acc1
```

Архивация работает без рассылки. Условия настраиваются переменными `ARCHIVE_*` в `.env.acc1`.

### Сбор участников

Интерактивный запуск:

```powershell
npm run parse:acc1
```

Сразу указать цель:

```powershell
npm run parse:acc1 -- @channel_username
```

Парсер умеет собирать всех участников, активных пользователей из истории сообщений или комментаторов постов канала. Результат сохраняется в `lists`. Для комментаторов дополнительно создаётся Excel-файл `*_comments.xlsx`: ник, ссылка, комментарий и дата.

После сохранения списка парсер предложит выбрать его для рассылки. Если ответить `Да`, он обновит `LIST_FILE` в текущем `.env.accX` и сбросит `progress-state.json` для выбранного `STORAGE_MODE`.

### Дедубликация списков

```powershell
npm run dedupe
```

Скрипт предложит выбрать два `.txt` файла из `lists`: из первого будут удалены совпадения со вторым файлом и дубли внутри первого файла. Результат сохранится отдельным `.txt` файлом.

### Планировщик

```powershell
npm run schedule:acc1
```

Время берётся из `SCHEDULE_HOUR` и `SCHEDULE_MINUTE` в `.env.acc1`. Если добавить `SCHEDULE_START_IMMEDIATELY=true`, первый запуск начнётся сразу.

### Где лежат данные

- `lists/` - списки пользователей и результаты сбора.
- `messages/` - тексты сообщений.
- `storage/` - прогресс, обработанные пользователи, дневная статистика и логи.
- `report.csv` - отчёт при общем режиме `STORAGE_MODE=shared`.
- `storage/acc1/report.csv` - отчёт при `STORAGE_MODE=per_profile`.

Чтобы начать рассылку заново, остановите скрипт и удалите нужные файлы прогресса из `storage` или `storage/acc1`.

## Архитектура

### Обзор

Проект — Node.js (ESM) приложение на базе библиотеки [GramJS](https://github.com/gram-js/gramjs), реализующее четыре независимых режима работы с Telegram-аккаунтами: рассылка, парсинг участников, архивация диалогов и планировщик. Поддерживается параллельная работа до трёх аккаунтов (`acc1`–`acc3`).

---

### Точки входа (`tools/`)

| Файл | Команда | Назначение |
|---|---|---|
| `tools/start.js` | `npm run start:accN` | Запускает рассылку или архивацию (`--archive`) |
| `tools/login.js` | `npm run login:accN` | Авторизует аккаунт и сохраняет `SESSION_STRING` в `.env.accN` |
| `tools/parse.js` | `npm run parse:accN` | Интерактивный сбор участников из групп/каналов |
| `tools/schedule.js` | `npm run schedule:accN` | Планировщик — запускает рассылку по расписанию (`SCHEDULE_HOUR`/`SCHEDULE_MINUTE`) |
| `tools/dedupe.js` | `npm run dedupe` | Дедублирует два `.txt` файла из `lists/` |

Каждый точка входа выставляет `process.env.DOTENV_CONFIG_PATH` на нужный `.env.accN` и импортирует логику из `src/`.

---

### Ядро (`src/`)

```
src/
├── index.js     — главный цикл рассылки и архивации
├── parser.js    — интерактивный парсер участников
├── config.js    — все константы и конфигурация
├── io.js        — чтение файлов списков и сообщений
├── progress.js  — сохранение/загрузка точки продолжения
├── storage.js   — множество обработанных пользователей
├── report.js    — запись строк в CSV-отчёт
└── utils.js     — вспомогательные функции
```

**`src/index.js`** — основной модуль. Подключается к Telegram через GramJS, проходит по списку получателей и отправляет стикер + текстовые сообщения. При ошибке `PEER_FLOOD` автоматически пытается снять ограничение через диалог с `@SpamBot` (функция `attemptUnblock`). При неудаче останавливает рассылку и запускает архивацию.

**`src/parser.js`** — интерактивный парсер. Поддерживает три режима сбора: все участники (`iterParticipants`), активные из истории сообщений (`iterMessages`), комментаторы постов канала (`messages.GetReplies`). Для комментаторов дополнительно создаёт Excel-файл через ExcelJS.

**`src/config.js`** — единая точка конфигурации. Определяет пути к файлам данных, параметры ограничения скорости, настройки стикера, условия архивации и параметры защиты от флуда.

---

### Конфигурация аккаунтов

Каждый аккаунт изолирован через собственный `.env.accN`. Ключевые переменные:

- `SESSION_STRING` — строка сессии GramJS (заполняется автоматически при входе)
- `LIST_FILE` — имя файла получателей из `lists/`
- `MESSAGE_FILES` — файлы сообщений из `messages/` (через запятую)
- `STORAGE_MODE` — `shared` (общее хранилище `storage/`) или `per_profile` (изолированное `storage/accN/`)
- `SOCKS_PROXY` / `SOCKS_TYPE` — прокси для подключения
- `ARCHIVE_*` — условия архивации диалогов

---

### Хранилище данных

```
lists/            — списки получателей (.txt, username или id:hash)
messages/         — тексты сообщений (.txt)
storage/          — общее хранилище (STORAGE_MODE=shared)
storage/accN/     — хранилище аккаунта (STORAGE_MODE=per_profile)
  ├── progress-state.json   — индекс следующего получателя
  ├── processed-users.json  — множество уже отправленных
  ├── daily-stats.json      — статистика за день и события блокировок
  └── connection-debug.log  — диагностика соединения
report.csv        — общий отчёт об отправках
```

---

### Ограничение скорости

| Параметр | Значение |
|---|---|
| Задержка между сообщениями одному получателю | 3 сек |
| Задержка между получателями | 60 сек |
| Размер пакета | 20 пользователей |
| Пауза между пакетами | 30 мин |

---

### Запуск и платформы

Проект поддерживает три платформы:

- **Linux** — скрипты `.sh` в корне проекта
- **macOS** — скрипты `.command` в папке `mac/`
- **Windows** — скрипты `.bat` в корне проекта
- **Docker** — `Dockerfile` + `docker-compose.yml` для контейнерного запуска
